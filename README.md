## Architecture Overview

## Overview

The Inventory Platform is an event-driven and service-oriented ecosystem designed to manage inventory operations, product distribution, business transactions, and cross-environment data integration.

The platform combines synchronous microservices, asynchronous messaging, PostgreSQL persistence, Python background processing services, RabbitMQ, Apache Kafka, Kafka Streams, and Apache Camel to support both operational and analytical workloads.

Inventory data is maintained and distributed by state, region, and branch. Business events generated by the platform are processed asynchronously through RabbitMQ consumers, where Python workers execute database procedures and business workflows. Database changes are captured through Change Data Capture (CDC) mechanisms and published to Kafka topics, enabling real-time event streaming and data propagation.

Kafka Streams and State Stores are used to enrich, aggregate, and process data in real time. Apache Camel acts as the integration layer, consuming events from Kafka and routing them to downstream systems through scalable and resilient processing pipelines.

The solution supports inventory management, payment processing, batch operations, analytics generation, reporting workloads, and external system integrations while maintaining scalability, traceability, fault tolerance, and operational reliability.

This architecture demonstrates the implementation of modern distributed systems patterns, including event-driven communication, asynchronous processing, change data capture, stream processing, enterprise integration, and real-time data synchronization.

## Components

### Inventory Service

Responsible for inventory management, stock movements, product availability, and inventory-related business operations. The service exposes synchronous REST APIs and publishes business events through RabbitMQ.

### Payments Service

Handles payment processing and transaction workflows. The service supports both synchronous communication and asynchronous event publishing through RabbitMQ.

### RabbitMQ

Acts as the messaging backbone between microservices and asynchronous processing components, enabling loose coupling and event-driven communication.

### Python Workers

Background processes (`eventos.py`, `ordenesii.py`, and `payment.py`) responsible for consuming RabbitMQ messages, executing business logic, and invoking database procedures and functions.

### PostgreSQL

Central persistence layer containing operational tables, views, functions, procedures, and batch processing components.

 
### CDC (Change Data Capture)

Captures database changes in real time and publishes them to Kafka topics, eliminating the need for direct polling mechanisms.

### Apache Kafka

Serves as the event streaming platform that distributes data changes across the ecosystem.

 
### Kafka Streams & KTables

Provides stream processing, enrichment, aggregation, and stateful event management through State Stores.

### Kafka Event Router (Apache Camel)

Consumes Kafka topics and distributes events across multiple independent destinations using parallel processing, SEDA queues, Circuit Breakers, and DLQ strategies.

### External Systems

Analytical platforms, reporting systems, statistical repositories, and third-party integrations that consume processed business events.

## Event Flow

1. Clients interact with Inventory and Payments services.
2. Business events are published to RabbitMQ.
3. Python workers consume and process events.
4. Database procedures update PostgreSQL.
5. CDC captures database changes.
6. Changes are published to Kafka.
7. Kafka Streams enriches and aggregates data.
8. Apache Camel routes events to downstream systems.
9. Sink Connectors distribute information to analytical and external environments.
